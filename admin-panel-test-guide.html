Before You Start — Setup

Do these steps once before running any tests
  • 1
    Log in as an Admin. Use the admin email and password provided by the developer. The admin account has special access to see all data.
  • 2
    Go to the Admin Panel. After logging in, navigate to /admin in the browser address bar (e.g. yoursite.com/admin). You should see the admin sidebar on the left.
  • 3
    Check the sidebar. You should see 14 menu items: Overview, Listings, Exchange Ledger, Tax & 1099, Users, Activity, TX Monitor, Growth & Funnel, Referrals, Liquidity, Credit Risk, System Health, Disputes, and Supply Map.
  • 4
    Make sure there is test data. Ask the developer to confirm there are at least a few users, businesses, and transactions in the system before testing.
If you cannot see the admin panel or it shows "Access Denied", the admin role has not been set correctly. Contact the developer.

Login & Access Control

Make sure only the right people can access the admin panel
#What to doWhat you should see
1.1Log out and try to visit the admin page directlyYou are redirected to the login page — not shown any admin data
1.2Log in as a regular (non-admin) user and visit the admin pageAccess is blocked — you see a message like "Access Denied" or are redirected away
1.3Log in as the admin user and visit the admin pageThe full admin panel loads with the sidebar visible
1.4Click each of the 14 sidebar items one by oneEach click loads the correct section — no blank white screens or error messages
1.5Click a sidebar item that has sub-items (e.g. Listings)The sub-items appear underneath it
1.6Refresh the pageAll sidebar sections start collapsed (none are pre-opened)

The homepage of the admin panel — shows platform-wide numbers at a glance
#What to doWhat you should see

2.2Look at "Total Users"A real number — not zero and not a placeholder like "—"

General Behaviour — Test on Every Section

These checks apply everywhere across the admin panel
#What to checkWhat you should see
13.1While a section is loading dataA spinning circle (loading spinner) is visible — no blank white area
13.2When a table has no dataA friendly message like "No results found" — not a broken or empty screen
13.3When you type in a search boxResults filter immediately as you type — no need to press Enter
13.4When you clear a search boxAll rows return — nothing stays filtered
13.5When a table has more than 10 rowsPage 1, 2, 3… buttons appear at the bottom of the table
13.6When you navigate to the last page of a tableOnly the remaining rows show (e.g. if 23 rows, page 3 shows 3 rows)
13.7When you save something (credit adjustment, dispute update, etc.)A loading indicator briefly shows, then disappears when done — no crash
13.8After saving, reload the page and come back to that sectionYour changes are still there — they were saved to the database
13.9View the admin panel on a small screen or tabletThe sidebar and content are still usable — nothing is cut off or broken

Known Limitations

These are existing gaps — not bugs, but features not yet fully built
  • Evidence file upload is not in the admin panel yet. The Disputes section can display evidence files, but there is no button to upload files from within the admin. Files must be added directly by the developer for now.
  • Data does not update live. The admin panel does not automatically refresh when new data arrives. You need to reload the page or click a "Refresh" button to see new information.
  • Some sync errors may not be captured. If a product sync crashes mid-process unexpectedly, the error might only appear in a developer log and not in the System Health section.
  • Security PIN is stored as plain text. The merchant POS security PIN is currently stored without encryption. This is a known security debt to be fixed in a future update.

How to Report a Problem

If something doesn't work as expected
  • 1
    Note the test number. For example: "Test 10.6 failed — the admin note was not saved after reloading."
  • 2
    Take a screenshot. A screenshot of what you see on screen is very helpful for the developer.
  • 3
    Describe what you did. Write down the exact steps you took before the problem appeared.
  • 4
    Describe what you saw vs. what you expected. For example: "I expected the note to appear after reloading but the field was empty."
